### A. `td-flowfield-builder.md` §3 Public API 추가

```markdown
#### blocked 배열 소스 (결정 필요: Option A/B/C)

**Option A — PCG Generator 직접 반환:**
`CityscapeGenerator.Generate()` 의 반환값 `GenerateResult` 에
`bool[,] BlockedTiles` 를 추가한다. Generator 는 building lot rect 를
FlowField 그리드 셀 인덱스로 변환하여 채운다.

PCG_Building_Cube.prefab 에 Trigger BoxCollider 를 추가 (HR-1 허용 범위).
레벨 로드 후 `Physics.OverlapBox` 로 blocked 배열을 채운다.

**Option C — CityscapeObstacleMap SO:**
Generator 가 building lot rect 목록을 별도 SO 에 저장.
FlowFieldBuilder 가 SO 를 읽어 blocked 를 채운다.

세 옵션 중 하나를 프로젝트 리드가 결정. 결정 전까지 `blocked` 소스는
**FT-01 (Spec Gap, TODO, blocking=true)** 상태.
```

### C. `design/proto-modules/_conventions.md` 에 가이드라인 추가

```markdown
### GUIDE-PCG-01. PCG 배치 오브젝트의 시각+데이터 이중 설계

PCG 모듈이 배치하는 오브젝트가 게임 시스템(패딩, 스폰 존, 타워 그리드 등)에서
역할을 가질 때, 설계 초기에 다음 두 경로를 동시에 명세한다:

1. **시각 배치 경로**: 어떤 프리팹이 어디에 배치되는가 (AssetSet 인터페이스)
2. **데이터 등록 경로**: 배치 오브젝트가 어떤 게임 시스템에 어떻게 알려지는가

어느 한쪽만 설계하면 "보이지만 게임이 모르는 오브젝트" 상태가 되어
FT-01 (Spec Gap) + FT-02 (Misfill) 연쇄 위험.
```

## Reason

CL-2026-04-24-004 (/verify 루프) 에서 `FlowFieldBuilder.Build(blocked)` 의
blocked 소스가 어떤 명세에도 정의되지 않음을 OR-01, OR-07 두 오라클 모두 FAIL 로
확인. 사용자가 "건물은 진입할 수 없는 지점" 을 도메인 룰로 확정(OR-08 Confirmed)
했으나 구현 방식이 미결정 상태. Blocking Escalation #5 발동.

PCG 시각 레이어와 FlowField 데이터 레이어 간 연결 인터페이스가 명세에 없음을
OBS-2026-04-24-001 에서 패턴으로 분류.

## Risk of Adoption

### A 적용 시
- PCG 그리드(blockSize 단위)와 FlowField 그리드(1m/cell 기본) 의 원점·해상도
  정합 미스로 blocked 위치가 시각과 어긋날 수 있음.
  완화: CellSize 를 `blockSize / N` 으로 강제하거나, 좌표 변환 함수 검증 필수.
- 실 에셋 교체 시 건물 footprint 가 lot rect 와 다를 수 있음.
  완화: 프리팹 교체 후 Option B 전환 또는 패딩 마진 추가 파라미터.

### B 적용 시
- HR-1 "Collider 는 트리거/질의용으로만" — Trigger Collider 는 허용 범위.
  단, Physics Layer Matrix 설정 누락 시 FT-P-003 위험.
- 런타임 OverlapBox 질의 비용: 건물 수 × 질의 = 수백 회. 레벨 로드 1회성이면 허용.

### C 적용 시
- SO 경유 결합 추가. HSR-002(SO 런타임 수정 위험) 주의.
  BuildDefaults 에서 에디터 타임에 채우면 런타임 수정 불필요 — 안전.
