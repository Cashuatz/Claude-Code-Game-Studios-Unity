# SpeechBubble — Camera 네임스페이스 충돌 및 verification gap

## Loop Goal
캐릭터 말풍선 UI(9-slice + 타이핑 + 빌보드) 최초 구현 후 Unity 컴파일 통과 여부 확인.

## Observed Signals
- `error CS0118: 'Camera' is a namespace but is used like a type` at SpeechBubble.cs(137,31)
- 사용자 지적: "검증 안 해? VKL 안 써?"

## Failure Taxonomy
- **FT-01 spec gap** — 해당 어셈블리에 `Proto.Camera` 네임스페이스가 존재한다는 문맥 확인을 생략.
- **Verification gap (meta)** — compile-check 스킬이 사용 가능한 상태에서 검증을 수행하지 않고 "Unity에서 컴파일 확인되면 알려주세요" 로 사용자에게 떠넘김. Verification(기계적 검증) 책임 회피.

## Oracle Evaluation
- **OR-01 direct observation** — `dotnet build Proto.csproj -nologo` → 경고 0 오류 0 (수정 후). PASS.
- **OR-09 spec coverage** — Show API 확장점(dismiss/hold/concurrency) 노출. PASS.

## Root Cause
C# 네임스페이스 해석 규칙: 현재 네임스페이스 `Proto.UI.Speech` 에서 단순 식별자 `Camera` 를 찾을 때,
부모 스코프 `Proto` 의 하위 네임스페이스 `Proto.Camera` 가 `using UnityEngine` 으로 가져온
`UnityEngine.Camera` 타입보다 **더 가까운 스코프**로 우선 해석됨 → 네임스페이스를 타입처럼 사용.

## Fix
`using UnityCamera = UnityEngine.Camera;` alias 를 파일 최상단에 두고,
`Camera` 타입 참조 6곳(필드/파라미터/`Camera.main` 4회)을 `UnityCamera` 로 교체.

## Decision
- 현재 네임스페이스 규약(`Proto.<Feature>`) 유지. 파일 단위 alias 로 해결.
- 동일 어셈블리에 `Proto.<Type식별자>` 네임스페이스가 존재할 경우 해당 식별자를 단순 이름으로
  사용하면 같은 충돌이 재발할 수 있음 — 체크리스트에 반영 권고 (후속 proposal 대상).
