# HYP-2026-04-24-001 — 공통 캐릭터 프리팹 전략 및 SpeechBubble 역할

## 내용

질문 C에 대한 **임시 가정**. 사용자 미응답 상태에서 Phase 0(공통 스모크 루프)을 진행하기 위한 최소 전제.

### 가정 C-1: 캐릭터 프리팹 재사용 전략

- **가정:** 현 `Assets/Proto/Prefabs/Movement/Unit_Base.prefab`(흰 큐브 Visual + MovementAgent + ProtoUnitTarget + ProtoEventEmitter + ProtoDebugInput)을 **3장르 공통 베이스로 유지**하고, 장르별로 필요한 시점에 variant prefab을 파생한다.
  - turn3d: `Unit_Turn3d_Party.prefab`, `Unit_Turn3d_Enemy.prefab` (스킨드 메시 후속 교체, 우선은 색상 다른 Cube)
  - td: `Unit_TD_Builder.prefab`(플레이어·건설자, 공통 Unit_Base 재사용), `Enemy_TD_Walker.prefab`(색상 변경 Cube + HP), `Tower_TD_Basic.prefab`(별도)
  - rail-shooter: 플레이어는 1인칭이므로 Unit_Base 불사용(Camera만), `Enemy_RS_Zombie.prefab`은 Unit_Base 파생.
- **근거:**
  - 현 Unit_Base는 장르 비특이적 프리미티브이며 MovementAgent는 HR-1 준수(RB 없음).
  - Proto CLAUDE.md 작업 규칙 — "빠른 반복 우선, 테스트는 선택".
  - `_catalog-td.md` Base에 `character-render-kit`가 포함되어 장르별 렌더 추상화 존재.
- **리스크 if 틀림:** 장르별 완전 분리가 필요하다고 판명되면 공통 베이스가 오히려 방해가 될 수 있음. 이 경우 variant 대신 장르별 독립 프리팹으로 전환. 전환 비용: 각 장르 씬 진입 시 프리팹 재지정 (중간 규모).
- **검증 방법:** Phase 1(TD) 진입 시 `Enemy_TD_Walker`를 Unit_Base 파생으로 만들어보고 MovementAgent 기반 경로 추적이 깔끔한지 OR-P-001로 확인. 만약 물리/렌더 충돌 발생하면 장르별 분리로 전환 제안.

### 가정 C-2: SpeechBubble의 게임플레이 역할

- **가정:** 초기 구현에서는 SpeechBubble을 **장식·튜토리얼 힌트 전용**으로 사용하고, 게임플레이 신호(데미지/쿨다운/상태)로는 직접 엮지 않는다.
  - turn3d: 스킬 사용 시 1회성 컷신 대사 (시각적 장식)
  - td: 기지(core-base) 경고·튜토리얼 팝업 (체력 바와 독립)
  - rail-shooter: 좀비 등장 시 조롱 대사 (공격 시스템과 분리)
- **근거:**
  - SpeechBubble 모듈은 이미 반응형 크기/테일 클램프/말랑 애니까지 완성되어 있어 변경 비용 낮음.
  - 게임플레이 신호로 엮으면 숨은 의존성(FT-02 Hidden Semantic Rule Misfill 위험) 증가.
- **리스크 if 틀림:** 사용자가 "말풍선을 핵심 기믹으로 원한다"고 응답하면 각 장르 스펙 재설계 필요. 현재 Proto 범위에선 드문 케이스로 예상.
- **검증 방법:** OR-08로 사용자에게 "SpeechBubble이 장식인지 게임플레이 기믹인지" 명시 확인 필요.
